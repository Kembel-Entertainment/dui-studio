# Rendering and editing contracts

Dialog geometry comes from `MenuTemplate.render`, `Canvas`, `Scene` and `RenderReport`; Studio does not implement another layout engine. Render backend order follows DUI's fixed image/font/head/model/item/effect layers. Popup suppression uses `Canvas.renderPlan`. Native viewport clips and finite `Motion` transforms are applied in preview.

GLSL bodies and modules come from public `PackContribution` values. The preview generates a typed parameter struct from `ShaderSpec`, loads its actual values and invokes the original function in a native OpenGL 3.3 framebuffer. The Paper color-bit encoding is not needed for the desktop image. The preview also loads DUI 0.2's matching generic shader utility prelude from its bundled pack resources; changing that DUI runtime resource requires an engine compatibility check. An unsupported shader produces its real compile error and a visible warning rather than a substituted illustration.

World projection uses `WorldMapGeometry` and consumer definitions. World HUD scaling uses logical surface anchors. These screens are independent of Minecraft GUI scale. Pixel previews fit immutable frames into the normalized `VideoSurfaceSpec` viewport and render its HUD. This verifies presentation, not packet throughput, network latency or game input entity behavior.

Native model preview resolves Minecraft item/model JSON and texture inheritance, element faces, model rotations and GUI transforms. Generated item layers, skin cuboid UVs, slim arms, outer skin layers and humanoid equipment textures are supported. Animated texture sheets are sampled at the preview clock. This is a desktop renderer, not a bundled Minecraft client: special item dispatches, complete entity animation, enchantment glint, arbitrary dye/pattern metadata and every Minecraft lighting behavior are not fully replicated. Unsupported cases are reported. Check final appearance in Minecraft before release.

Drag and resize work on explicitly identified rendered components with static geometry. Bound/repeated geometry is inspected in the template and edited through its bindings/fixture; Studio refuses to silently replace a dynamic expression with a number. Source editing always remains available. Grouping retains consecutive sibling source, including intervening comments. Some layout contexts need a consumer-selected explicit group size.

The Java process owns one native context, bounded asset/texture/program caches and one in-flight request. Rust retains only the latest PNG with its revision. The UI debounces requests and never queues animation frames while a render is busy. Bounds are capped at 2048×1152 and private live media remain outside version control. Adapters are trusted code, not a security sandbox; the frontend receives only project-scoped Rust filesystem operations.
